# 共通制作依頼：パンチのコミックVFX

目的：同一モデル・同一仕様から、確認方法だけを変えて制作し、確認コストと品質の見落としを比較する。個々の生成結果の差があるため、1組で一般的な優劣を断定しない。

## 共通仕様

- お金のない映画制作会社の、ぬいぐるみ調・ローポリの協力バカゲー。拳が当たる瞬間の一発のVFX。SFレーザーや大爆発ではなく、漫画の殴打記号が少し立体的に飛び出す印象。
- 主役：不揃いで太い放射状の衝撃形。暖かなクリーム・黄・オレンジ、暗い茶の輪郭。細い白線・円の粒をつないだだけ・ネオンの輪だけで済ませない。
- 参考：既存 `godot/vfx/shaders/comic_impact.gdshader` の塗りと輪郭を出発点に、古典カートゥーンの不揃いな衝撃記号を題材にする。特定の作品や既存VFXの完全再現ではない。
- 時間：0〜0.08秒は短い振り抜きの前触れ、0.10〜0.16秒に明確なヒット、0.16〜0.45秒に前方への押し出しと追従、0.45〜0.90秒にほぐれて退場。通常速度 `speed=1`。視認性のためピーク形は少なくとも数物理コマ読めること。
- 空間：接触点を中心に最大およそ幅1.0〜1.4m。高さ1.7mの参考人形と同じ撮影台で確認。打撃方向+X、横と斜めだけでなく+X正面からも読む。人物の顔を覆う全画面フラッシュやカメラ揺れは使わない。
- 主役の供給は拳の運動。先行する衝撃の肩・先端、遅れる短い尾・二次の裂片を時間差で動かす。全体のscaleだけを変える静止スターにならないこと。
- 終わり：衝撃は前方へ抜け、根元から材料の供給が途切れる。外の少数の裂片は速度を落として落下/曲がりながら抜ける。全部同じフェード、同じノイズの穴、元の場所へ戻る、同じ縮む円は禁止。寿命は1.2秒以内、1.5秒時点にはノードも片付く。
- 個人 `vfx-flow` とプロジェクトの `godot-vfx/PLAYBOOK.md` に従う。技法名やノード数で合格にせず、全体・主動作・退出の隣接コマで判断する。

## 共通APIと担当制約

- 自分の専用フォルダ内だけを編集し、両案を独立した完成VFXとして残す。共有のラボ登録・ゲームコード・共通部品は親が担当する。もう一方のコードや画像を読まない。
- `vfx_base.gd` を継承。`static func spawn(parent: Node, pos: Vector3, size: float = 1.0, direction: Vector3 = Vector3.RIGHT) -> Node3D`。位置を決めてから構築。`_tick` は `age` を使い、Shader TIME/Tween/壁時計に依存しない。class_name不要。
- 独自シェーダーは自分のフォルダ内。既存部品は読み取り利用可。標準ライブラリ中心、素材出典を偽らない。画像編集が必要なら規定の画像生成ツールを使う。
- 共通撮影台：`res://addons/dev_session/benchmarks/punch_stage.tscn`。固定シード431、60Hz、同一カメラ、23時点×3方向、640×360。撮影台は基底の `_process(1/60)` を物理コマごとに手動実行して時計を固定する。
- 撮影には `python tools/punch_workflow_trial.py --mode <指定> --variant <指定> --effect <自分のresパス> --iteration <番号>` だけを使う。GPU はファイルロックで逐次実行される。エディタ・見えるウィンドウを開かない。セッションは同じPIDで再利用する。
- 初回撮影をcycle_00、視覚問題からの修正を01以降。合格なら過剰に繰り返さない。問題が残る場合は最も目立つ1〜2点に絞って少なくとも3回の修正を行い、最大6回。毎回「観察→仮説→変更→同条件で再撮影」を記録する。
- 全画像をローカル保存する。渡された一覧が小さく判断できない場合は、元のPNGを追加で読んでよい。その読み込みを記録し、節約のために曖昧なまま合格にしない。
- 完了時は専用セッションを `--stop` で止める。コミット・pushは親が行う。

## 完了成果物

専用フォルダのVFXと、同じフォルダに `author_report.json` を作成する。内容：開始/終了UTC、各cycleの観察・変更・見た全画像パス・自己判定、未解決点、APIと寿命。モデル思考の量を文字数から捏造しない。全体/動き/終わりを確認し、通常速度の動画視聴と静止コマの確認を区別する。

最後に親が両案を共通の細かいコマ割りで別撮影し、名称を伏せた品質レビューを行う。その共通確認のコストは制作中の節約とは分けて計上する。
