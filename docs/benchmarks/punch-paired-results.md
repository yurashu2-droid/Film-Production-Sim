# パンチVFX：同じ修正課題5組で再比較

2026-10-11。今回の限定的な修正では、圧縮確認が5組中4組で速く、1組は0.19秒遅かった。品質の見落としは検出されなかった。時間短縮は約7.5%、新規入力トークンの削減は約2.3%で、効果は小さい。

**運用判断：単純な修正の途中確認には圧縮を使える。新しいVFXの制作と最終の品質確認は全コマを見る。** 常駐Godot・まとめ撮影・短いログは両方で使う。画像の圧縮・間引きをすべての作業の標準にはしない。

## 前回との違い

前回は別々の新作VFXを制作させたため、生成したコードや修正回数の違いが混ざった。今回は同じ既存パンチに同じ不具合を入れた、byte単位で一致する候補を各組に2つ用意した。[共通依頼](punch-paired-brief.md)に従い、指定された問題だけを直した。

両担当は `gpt-6.1-sol / high`、もう一方の候補や正解GDを読まない。左担当は1→5、右担当は5→1の順。方式を交互に割り当て、両担当が両方式を使った。全コマ方式と圧縮方式のそれぞれが、実施順の1〜5番目を1回ずつ占める。

**両方式とも常駐・まとめ撮影（2 RPC）・短い数値ログに揃えた。違いは、全23時点×3方向の一覧3枚を読むか、選択8時点×3方向の一覧1枚を読むかだけ。** 元PNGは両方とも全て保存し、必要なら追加閲覧可。今回は追加閲覧はなかった。ウォームアップは計測前に実施した。

## 修正完了までの時間

候補を読む前のstartから、修正後の画像を確認し記録したfinishまで。GPUの順番待ちを差し引いた値。

| 修正課題 | 全コマ | 圧縮 | 圧縮の短縮量 |
|---|---:|---:|---:|
| 大きすぎる衝撃 | 37.72秒 | 34.77秒 | 2.96秒 |
| 遅れるヒット | 38.74秒 | 35.19秒 | 3.55秒 |
| 逆向きの進行 | 35.32秒 | 35.51秒 | −0.19秒 |
| 主層の動き・退出が停止 | 40.00秒 | 36.11秒 | 3.89秒 |
| 見えなくなったノードが残る | 38.08秒 | 33.99秒 | 4.09秒 |
| 合計 | 189.85秒 | 175.56秒 | 14.29秒 |

合計で7.5%短縮。組ごとの短縮率の中央値は9.2%。待ち時間を含む合計は191.46秒→176.16秒で、結論は変わらない。撮影・一覧生成の合計は27.41秒→21.85秒。全10件とも、変更前と修正後の2回の撮影で完了した。

最も悪かったのは逆向き修正の0.19秒の遅れ。少数の試行での小さい差なので、すべての作業が速くなるとは言わない。これまでの結果と合わせると、画像を減らす効果は作業内容に依存する。

## トークンと追加確認

| 5課題の計測区間合計 | 全コマ | 圧縮 |
|---|---:|---:|
| 新規入力トークン | 46,065 | 45,016 |
| キャッシュ入力トークン | 1,790,976 | 1,793,536 |
| 出力トークン（推論を含む） | 3,564 | 3,573 |
| 報告された実読画像 | 31枚 | 11枚 |
| 実読画像の元画素数 | 50,457,600 | 16,972,800 |
| 元PNGの追加閲覧 | 0 | 0 |

新規入力は2.3%減ったが、キャッシュを含む総入力は1,837,041→1,838,552で0.08%増え、出力もほぼ同じだった。**トークン全体を大きく減らす方法だとは評価できない。** 元画素数は約66%減ったが、画像・文章それぞれのトークン内訳は分離できないため、元画素数の減少をそのままトークン減少として扱わない。

組ごとでは、ノード片付け課題の圧縮側だけ新規入力が12,556で、全コマ側9,231より多かった。他の4組では圧縮側が少なかった。良い平均だけで判断せず、この増加も集計に含めた。

トークンは担当のCodexログの累積 `token_count` を、start/finishマーカー直前の値で引き算した。新規入力は入力−キャッシュ入力。キャッシュ入力は入力の内数、推論出力は出力の内数。画像の列挙は担当の実読記録に基づく。

共通資料の読み込み、課題間の思考、最後の報告など計測区間外は別集計。両担当の区間外の合計は新規入力40,432・キャッシュ入力555,520・出力1,620。これを各方式の利益に振り分けていない。親のツール準備・集計・レビュー費用も上の比較には含まない。この実験そのものが14秒で済んだという意味ではない。

## 品質と検証

各結果を別の共通監査で、同じ正解パンチと比較した。1案につき46時点（2物理コマ刻み、0〜1.5秒）×3方向、640×360。**全10案・計1,380枚が正解画像と画素単位で一致した。** 今回の修正による見た目の違い・抜けは撮影したコマで検出されなかった。

描画ログのエラー0、1.3秒以降の残存ノード0。ソースの寿命設定も1.05秒または1.1秒で仕様内。動的な残存チェックは1.3秒以降であり、1.2秒の境界そのものを検証したという主張はしない。共通監査のエンジン内処理合計は28.463秒で、上の制作比較から除外した（起動・画像比較・親の判断時間は含まない）。

親も修正後の全体・主動作・退出の一覧を確認した。既存VFXの板っぽさなど、前回指摘された見た目自体の改善は今回の対象外で、その弱点は残る。等速動画を視聴したという評価ではない。コマ間に隠れた不具合や別カメラ・別背景での品質を保証するものでもない。

構成・トークン区間の関連テスト2本成功、Python構文確認成功。測定方法のコードレビューで重大な誤りなし。本編ロジックは変更していないため、フルゲームテストは繰り返していない。
