# 同じパンチVFXを直す5課題の共通依頼

目的は新しいVFXの制作ではなく、同じ不具合を同じ仕様で直すときの確認方式の比較。担当は割り当てられた順番で5課題を一度ずつ処理する。既存の漫画パンチの色・形・構成を維持し、指定された問題だけを直す。

共通の見た目：暖色、茶輪郭、不揃いの漫画衝撃。拳が+Xへ進み、0.10〜0.16秒にヒット、0.16〜0.45秒に前進と追従、0.45〜0.90秒に根元から切れて抜ける。幅は約1.0〜1.4m、参考人形は1.7m。等速、寿命1.2秒以内、1.5秒にはノードも片付く。元の板っぽさの作り直しは今回の範囲外。

## 手順

1. 共通資料を最初に読み終える。その後、各課題の `start` を実行してから候補コードを読む。startの返答がその課題の依頼文・方式・ファイルパス。startは二度実行できない。
2. 指定方式でcycle_00を撮影し、返答の画像を実際にすべて見る。圧縮一覧が不十分なら元PNGを開き、その絶対パスを記録する。
3. 原因を絞り、現在の課題の候補 `punch.gd` だけを変更する。元の正解GD、他課題の候補、もう一方の担当のファイル・ログは読まない。共有shaderは読み取り可。
4. 同じ方式でcycle_01を撮影し、実際に画像をすべて見る。必要な場合のみ追加修正・撮影。不要なテストや追加機能は作らない。
5. 候補と同じフォルダの `review.json` に観察・変更理由・`inspected_images`（実際に見た全画像の絶対パス）・残る問題を記録し、`finish` を実行する。次の課題はfinish後にstartする。
6. 5課題の完了後は報告だけ返す。Godot停止・集計・コミットは親が担当する。

```powershell
python tools/paired_vfx_benchmark.py start --worker <指定> --case <指定>
python tools/paired_vfx_benchmark.py capture --worker <指定> --case <指定> --iteration 0
# 候補だけを修正
python tools/paired_vfx_benchmark.py capture --worker <指定> --case <指定> --iteration 1
python tools/paired_vfx_benchmark.py finish --worker <指定> --case <指定>
```

保存先はstartが示す。エディタや見えるゲーム画面は開かない。両方式とも同じ常駐Godot、まとめ撮影（2 RPC）、短い数値ログ、同じ23時点×3方向、シード431、60Hz。差は返答の画像が全23時点の一覧3枚か、指定8時点の一覧1枚かだけ。返答の `images` 全部を見る。GPUはロックで逐次撮影する。shaderの編集は不要。TIME/Tweenや時計を変更しない。

`review.json` の例：

```json
{"observations": ["初回の観察", "修正後の観察"], "fix_summary": "何をどう直したか", "inspected_images": ["絶対パス"], "residual_issues": []}
```

最後に親が両方式の結果を同じ全コマで確認する。通常速度の動画を見たとは書かず、固定時計のコマ列の確認と区別する。失敗や追加で開いた画像も費用に含める。
