# Pixel surge pack — meteor / lightning / fire wave / plasma

`px_base.gd` の12fps時間、UVセル、5色を引き継いだ独自の4案。既存Pixel炎の配色と、先肩・遅れ首・供給履歴で主形を作る個人vfx-flow手順を参照した。外部画像のトレースや`res://vfx/`の依存はない。

全て `spawn(parent, foot_position: Vector3, size=1.0)`。足位置ZEROから作る。シェーダーは専用 `px_surge_flow`、`px_surge_ground`、`px_chain_arc`。ソース停止・幾何の局所細分化・順序付き消費で終了し、寿命によるノイズ穴消しは0層。1エフェクト毎に暗外層、中間層、短い明層の3層があり、遅延と奥行きをずらす。

隕石は .2 供給開始、1.72 接地。履歴の先頭を太く、首を細くし、尾の最後の供給も地表へ進める。接地火舌と10個の固体小石、地表の圧力帯へ渡す。火舌は上へ、小石は下へ、帯は周方向へ消費する。

放電は .65 / 1.35 / 2.15 の三回。各回の3分岐は別の左右方向と折れを持ち、上空から導電路の前線が下へ進む。供給停止も上から下へ渡し、地表の導電路が冷えて枝先から順に消費する。3枚はZ間隔と向きを変えている。

火炎波は .25 / .90 / 1.55 の三対。中央床から左右へ、先肩を低い厚腹が追う。履歴行は進行方向に並び、各行の放出時刻が異なる。供給停止後は完成した肩を維持せず、3個の局所舌へ分離し、各舌が前・上へ進みながら細くなる。

プラズマは 0〜1.1 圧縮、1.1 射出、2.18 着弾。圧縮路の古い供給を先端へ送り出し、短い頭が右へ進む。着弾も右へ進み、上下の肩は短く開き、供給元から先へ消費される。

## 描画確認

Godot 4.7.2 CLI / Forward+ / NVIDIA RTX4060、60fps撮影台、主形更新12fps。全体8枚・0.1秒間隔のflow8枚・終盤8枚を各4種で実際に開いた。近景距離6でも隕石flowとプラズマwholeを確認した。対象の全撮影コマンドはexit0、GDScript/shaderエラーなし。統合の全テストと通常速度の動画評価は親担当で、ここでは動画を再生していない。

確認した8項目：

1. **因果**：隕石の降下→接地、放電の上→下、波の中央→左右、プラズマの溜め→右射出の位置変化が8枚に現れる。
2. **先行と遅れ**：隕石の頭/首、波の肩/腹、プラズマの頭/短尾は同一オブジェクトの拡縮を使わず履歴座標から再構成する。
3. **形の変化**：火炎波の布状の大面とプラズマの着弾後の輪が初回で目立ったため、低い腹・局所舌、短い前方出口へ実修正した。
4. **奥行き**：隕石/プラズマは輪郭に対する周方向の疎なメッシュ、火炎波は開いた曲断面、放電は間隔と角度が違う3枚。距離9では青の細層は弱い。
5. **色**：5色ランプ、暗外層/色の中層/短い明芯を実描画で確認。火炎波の左側は見る角度によって外面が幅広く見える。
6. **退出**：終盤8枚で地面帯の周方向消費、地表導電路の枝先消費、波の局所舌、プラズマの短い前方片を確認。大きな面を全体透明度で隠す終了は使っていない。
7. **光と接地**：明色に対応する3Dライトが床を照らす。白箱と1.7m人物で規模を比較。隕石接地と床部品は足位置から計算する。
8. **時間/負荷**：フレーム毎RNGなし、12fpsのみ主形再生成。1発あたりの薄層は3、固体の補助小石のみMultimesh。画像確認に必要な範囲だけ再撮影した。

画像はignored `godot/tests/shots/vfx_review/px_<id>_whole_ms.png`, `_flow_ms.png`, `_end_ms.png`。追加 `_flow_close_ms` と `_whole_close_ms` がある。Fire waveの終盤範囲は3.2〜3.9（旧3.9〜4.6ではほぼ空になるため）。life終端0.5秒前の4.6秒も空であることを確認した。

残る評価点：火炎波の主波は角度によって弧/開いた布に近い輪郭が一部残る。隕石とプラズマは遠景だと粒と層が小さく、プラズマの圧縮相は巻いた殻に見える瞬間がある。放電は平面を3Dにずらす方式のため真横では細い。ユーザーの見た目評価を成功扱いにはしていない。
