# 制作会社のゲームループ Implementation Plan

> **For agentic workers:** executing-plansで親が進行と同期を実装し、独立した素材・事務所・HUDを並列統合する。ユーザー指示により追加承認なしで実装する。

**Goal:** 受注から納品して事務所へ戻るまで、ソロと友達で一周できる。
**Architecture:** production_main.gdが既存main.gdを継承し、production_flow.gdに会社/現場進行を置く。既存撮影・判定・同期・再生を保持し、別の通常起動シーンを用意する。
**Tech Stack:** Godot4.7.2 GDScript、既存GLB、ENet。
**Spec:** 2026-10-08-design.md

## Global Constraints
- テキストだけで実装、GodotエディタUIは使わない。

## 次の改善単位：現場別の追加注文とNG日誌

既存の3場面を基本報酬の条件として保持し、各現場に追加注文を1つ付ける。倉庫は一発OK、スタジオはスタッフ映り込みなし、野外は月を2秒映す。基本撮影の成立に加えて選んだ注文を満たせば150コイン追加。失敗しても基本報酬から引かない。

本番中に実際の撮影カメラでスタッフの映り込みと月の映り時間を計り、テイクごとに保持する。精算は選んだテイクの記録を使う。NG日誌はその実測から短いこぼれ話を作る。予定外の出演を笑える思い出にし、ルートごとに準備と役割分担を変える。

検証は既存productiontestに選択テイクと期限失敗の支払い境界を追加し、実画面の一周を1回確認する。既存撮影判定・アニメーション・VFX素材は変更しない。

## 次の改善単位：制作班の「ここ！」目印

準備中に友達へ場所・道具を伝えやすくする。Vまたは中クリックで視点から物理面へ指示し、全員の画面に発信者名と道具名（地面なら「ここ！」）の目印を5秒表示する。各人1個で更新、発信間隔0.7秒、範囲30m。UI操作中・移動・結果・再生中は発信しない。目印はプレイヤー用表示で撮影映像には映さず、追加報酬の映り込みにも数えない。効果音は既存UI音を控えめに使う。

## 映画を持ち帰る・友達へ渡す

結果のNG日誌を納品前にも見せ、選んだテイクの笑いどころを残す。Pで通常の見返しを開始し、映画用SubViewportの8時点を2列4行PNGと個別PNG/JSONへ保存する。出力は各プレイヤー自身のuser://film_stills/。途中終了・期限切れで8枚未満なら中断し、未完成画像を保存しない。MP4は診断用連番から外で生成し、ゲームへエンコーダは持ち込まない。

- [x] 実際のfilm画像のコマ保存、寸法・中断・参加者経路を確認。競合する別テイクの見返しは開始承認のtokenで区別し、取り違えを防ぐ。
- [x] Windows用の起動パッケージをローカルに作り、配布する内容と初回起動を確認。Godot本体＋資源のportable方式を使用。

## 到着・最低予算の確認

現場へ大移動するkinematic荷物の足場速度を抑える。参加者の位置送信は制作モードの移動世代で区別し、旧位置が到着後に戻らないようにする。配置順も各マシンで一致させる。既存の通常移動は保持し、四人の到着後24物理tickと途中再参加で確認する。

残金0・無料廃材だけ・固定4か所を守った実描画撮影を確認し、無料でも満額まで成立することを確かめる。
