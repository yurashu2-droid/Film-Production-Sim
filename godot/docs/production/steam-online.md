# Steamでオンライン撮影

現在の制作ゲームをSteam通信で遊べる入口を追加した。最大4人で、ホストの会社番号を共有して参加する。
フレンド招待・検索画面・ホスト移譲は今回含めない。

## 遊び方

1. 全員が同じ版のゲームを用意し、各自のPCで別々のSteamアカウントへログインする。Steamはオンライン状態にしておく。
2. ホストは起動画面の「オンライン（Steam）」を選び、「会社を開く」。
3. 右下に表示される会社番号をF8でコピーし、参加者へチャットなどで伝える。
4. 参加者は起動画面の入力欄へ会社番号を貼り付け、「番号で参加」。

SteamのP2P通信を使うため、同じLANやルーターのポート開放は不要。制作進行・道具・キャラクターの同期には既存のゲームRPCを使う。
Escメニューで会社を出られる。ホストが会社を閉じた場合、参加者も起動画面に戻る。
参加失敗や25秒のロビー応答待ち、30秒の接続待ちでは状態を片付けて再試行できる。

同じLANのIP接続も残してあり、起動画面の選択欄を「同じネットワーク（IP）」へ切り替える。
ソロではSteamを初期化しないので、Steamなしでも起動できる。

## Windows配布版

`godot/tools/build_portable.ps1` はゲーム本体・PCKに加え、Steam用DLL、`steam_appid.txt`、GodotSteamのライセンス、オンラインの案内を同梱する。
配布するときは出力フォルダー全体を渡す。exeだけでは起動できない。
作業ツリーから作る場合は `-EngineDirectory` で既存エンジンのフォルダーを指定できる。

```powershell
& godot/tools/build_portable.ps1 -OutputDirectory artifacts/FilmProductionCrew-steam
```

開発確認用のApp IDは480。販売・公開時は自分のSteam App IDを `project.godot` の `[steam]` / `app_id` に設定し、配布用の `steam_appid.txt` も合わせる。
GodotSteam自体の利用料はない。Steamへの公開手続きと本番App IDの取得は別作業。

## 実装と確認

- `steam_session.gd` が初期化・会社ロビー・識別タグ・版確認・待機期限・退出を担当する。
- `net.gd` がSteamMultiplayerPeerを作り、参加者間通信をホスト経由にする。ホストへの接続ではロビー所属と4人上限も確認する。
- `features/online_room.gd` は登録の土台から番号表示を追加する。撮影用の映像には表示しない。
- `steam_session_test.gd` はSteam未ログイン、不正な番号、64bit番号、別ゲーム・別版、同一アカウント、退出、キャンセル・時間切れ後の遅い応答を確認する。
- `steam_host_test.gd` は実Steamサービスを使う任意の検証。会社作成、ネイティブ通信ホスト、ゲーム起動、表示範囲、ロビー識別と人数上限、会社終了を確認する。Steamへのログインが必要なので通常の自動テストとは分ける。
- `steam_quit_test.gd` は会社を開いたままアプリを終了する確認。Steam API終了前に通信を閉じる。
- 既存の開始メニュー通信テストはIP接続を明示し、二つのプロセスで参加者・ローカル操作・会社の座標を確認する。
