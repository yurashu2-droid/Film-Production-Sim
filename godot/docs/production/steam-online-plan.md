# Steamオンライン接続の設計・実装計画

目的: 起動画面からSteamの会社を開き、会社番号を入力して最大4人で現在の制作ゲームへ参加できるようにする。
フレンド招待、ホスト移譲、一時フォルダーの削除は今回の範囲外。
Godot 4.7.2 / GodotSteam 4.23.1、開発用App ID 480を使う。

## 構造

- `scripts/steam_session.gd`: Steam初期化、ロビー作成・参加、ゲーム識別タグと通信版の確認、25秒の待機期限、退出。
  Steam APIを渡せるため、外部サービスの失敗・遅延は小さな模擬APIで確認する。
- `scripts/net.gd`: 既存ENetに加えてSteamMultiplayerPeerを設定する。クライアント間の通信はホスト経由。
  ロビーは4人上限。接続時にもロビー所属と人数を確認する。
- `scripts/start_menu.gd`: オンライン（Steam）とIP接続の選択、番号入力、接続・切断・再試行。
  ゲームとRPCの準備ができてから接続を受け付ける既存の手順を使う。
- `scripts/features/online_room.gd`: 登録の土台で会社番号・人数を制作班の画面へ表示。F8で番号をコピーする。
  中心のゲームファイルと撮影映像には表示を追加しない。

## 完了条件

Steamでロビーと通信ホストが作られ、番号入力からホストのSteam IDへ接続する。
ゲームの参加者、道具、制作進行は既存RPCを使う。失敗や退出後にメニューから再試行できる。
別アカウントでの二人接続は利用できる実機に応じて実施し、未確認の場合はその範囲を明記する。

- [x] 画面を確認し、遊び方と確認範囲を記録する。

確認の重点: Steam未起動、無効な番号、別ゲームのロビー、キャンセル後の遅い応答、ホスト切断、5人目の接続。
前の作業で実行済みの全体検証の既存失敗には、この変更に関係がある場合だけ対応する。

## 実装・検証の記録

2026-10-14: ロビーの単体テストを未実装状態で失敗させ、その後成功を確認。実Steamで部屋番号・4人上限・ネイティブ通信ホスト・ゲーム起動・退出を確認。
仕組み登録とIP接続の二人テストが成功。実描画で発見した表示位置の不具合は、画面内の矩形確認が失敗することを確認してから修正した。
接続中のアプリ終了で終了コード1を検出し、ソケットをSteam APIより先に閉じる修正後に終了0を確認した。

変更セットの別担当レビューで見つかった3点（拒否した接続の登録解除、作成タイムアウト後の再試行、ホスト作成中の古い参加応答の退出）をまとめて修正。
タイムアウト・古い参加・自動入室の追加ケースは修正前に失敗し、修正後に成功。所属チェックの切断はネイティブ通信管理の公開APIを使う。
作成をキャンセルした直後は応答か25秒の期限まで新しい作成を待たせる。応答が消失しても期限後に再試行でき、入室応答だけ届いたロビーも後始末する。

判断: フレンド招待と一時物の削除は依頼に合わせて延期。配布できるWindowsフォルダーも作る。
別アカウント・別PCはこの環境では確認できていないため、実際の二人Steam接続を検証済みとはしない。

配布フォルダーのexeとPCKだけをゲーム資源として使い、実Steamで会社作成・本編起動・番号表示・会社終了・接続中のアプリ終了を確認。いずれも成功、終了0。
IP切断テストには「peer_left接続は1件」という古い固定値があり、既存の接着・カメラ切替の接続もあるため不一致だった。退出前と再生成後の接続件数が一致する確認へ直し、重複・取り残しを引き続き検出する。
修正後のIP切断ペアはホスト・参加者ともSTARTMENUTEST_OK、終了0。
