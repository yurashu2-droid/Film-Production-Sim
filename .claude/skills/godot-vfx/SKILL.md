# Godot VFX（コードだけで作る）

## 最初に読む：見た目の完成判断

**流れが画面で読めることが合格基準。頂点変形・シェーダー・移流・多層化・ノイズ不使用・テスト通過は、それ自体では見た目の合格理由にならない。**

素材・力と供給元・先行する部分・遅れて追う部分・曲がりや首や分岐の変化・供給停止後の行き先を短く設計する。通常速度の中盤を先に見て、固い個体の伸縮、完成した曲線のうねり、固定した殻に流れる模様へ寄っていたら、細部を盛る前に主役の流れを直す。

2026-10-08の5モチーフ案は、提示後に指摘があり、流れの要求を反映できていなかったと制作側も認めた。**成功の見本ではない。**「描画して直した」「中心線や局所幅が変わる」「素材ごとに消える」を理由に完成扱いした判断を繰り返さない。

再利用する個人スキルは `C:/Users/raito/.codex/skills/vfx-flow/SKILL.md`（`$vfx-flow`）。そちらは流れ・素材・判定の方針、このファイルはGodot部品と実装方法を扱う。個人スキルが存在しない環境でも上の完成基準は適用する。

このプロジェクトのVFXは `godot/vfx/` にまとまっている。エディタは使わず、
GDScript とシェーダーで組む。画像を参照する効果は `godot/assets/vfx/` の該当素材と出典も必要。
別プロジェクトへ移す時はスクリプト・シェーダー・画像の `res://` 依存を確認する。

作業は必ず **書く → 描画して画像を見る → 直す** の順で回す。画面なし（headless）の実行では
シェーダーの誤りも見た目も確かめられないので、見ずに「できた」と言わない。

## 使い方（呼び出し）

スクリプトは `class_name` を使わず、`preload` して呼ぶ（エディタを開かないと `class_name` は登録されない）。

```gdscript
const VfxExplosion := preload("res://vfx/vfx_explosion.gd")
VfxExplosion.spawn(self, pos, 3.2, 1.25, true)   # 親, 中心, 火球の半径m, 地面までの距離(負で空中), 全部入りか
VfxExplosion.fuse(box, pos, 0.8)                 # 爆発前の溜め（秒）

preload("res://vfx/vfx_fire.gd").spawn(self, pos, 1.0, -1.0)        # 大きさ, 秒数(0以下で出しっぱなし→ extinguish())
preload("res://vfx/vfx_smoke.gd").spawn(self, pos, 1.0, -1.0, false) # flat=true で影なしの簡略版 → stop()
preload("res://vfx/vfx_lightning.gd").strike(self, ground_pos, 1.0, 14.0)
var shot := preload("res://vfx/vfx_projectile.gd").fire(self, from, to, {
	"palette": "arcane",   # fire / arcane / venom
	"travel": 0.8,          # 届くまでの秒数
	"buildup": 0.6,         # 溜め。弱い弾は 0
	"ease": "in",           # linear / in / out
	"arc": Vector3(0, 2.5, -3),  # 経路を曲げる量
	"hit": true,            # false なら当たらず消える
})
shot.impacted.connect(func(pos, dir): pass)   # 着弾の合図
```

走りの演出は `project.godot` の `vfx/dash_dust_style` で選ぶ：
`sculpted` / `mesh` / `kenney`（土ぼこり）、`smear`（スミア＋風の線）、`volt`（スミア × 雷）、`thunder`（雷の疾走）、`kick`（蹴り上げの土ぼこり）、`scramble`（脚ぐるぐる＋蹴り上げの土ぼこり）。
`scripts/main.gd` の `RUN_FX` に登録してあり、`burst(direction, size, trail)` と `runner`（走者）を受け取る約束。
走っている間ずっと続くものは、走者ひとりにつき1ノードだけ生かし、合図のたびに `feed()` で延命する（`vfx_run_*.gd` が例）。

## 新しいエフェクトの作り方

0. **先に参考元を決める。** 作る前に「どのアニメ・ゲームのどの表現か」を調べて名前で言えるようにし、コードの先頭コメントに書く。
   参考なしで「光らせれば格好いい」と作ると失敗する（下の「絵柄に合わせる」を読む）。
1. **役割で層に分ける。** ひとつの見た目で全部を表そうとしない。
   - 一発もの：予兆（溜め）→ 閃光（数コマ）→ 本体 → 飛び散るもの → 余韻（煙・残り火）
   - 飛び道具：溜め → 発射の閃き（短く。主役を奪わない）→ 頭・軌跡・補助 → 着弾（進行方向へ強く）
   - 強さに比例させる。強い技ほど溜めも着弾も大きく。弱い技は溜めなしでよい
2. `vfx_base.gd` を継ぐ。`at(秒, 関数)` で一度きりの予約、`over(開始, 長さ, func(k))` で 0〜1 の変化、
   `life` 秒で自動的に消える（0 以下なら消えない）。Tween は使わない（一時停止・コマ送りに従わせるため）。
3. 部品は `Lib`（`vfx_lib.gd`）から取る。
   - `sprite(形, 色, 大きさ, billboard)`：0 丸い光 / 1 輪 / 2 閃光
   - `Lib.particles(メッシュ, 材質, Lib.process({...}), 数, 寿命)` → `emit(粒子, 遅れ, 位置)`
   - `Lib.cloud_mesh(0〜2)` ＋ `cloud` シェーダー：煙・火球・土煙。粒子の色のアルファが「残り具合」で、0 に近づくと穴が開いて消える
   - `Lib.streak_mesh()` ＋ `spark` シェーダー ＋ `particle_flag_align_y`：進む向きに伸びる火花
   - `Ribbon.new()` ＋ `ribbon` シェーダー：`draw(点の列)` を毎フレーム呼ぶ
   - `Lib.ramp([[位置, 色], ...])` 色の移り変わり、`Lib.curve([[位置, 値], ...])` 大きさなどの曲線
4. `static func spawn(parent, pos, ...)` を用意し、**位置を決めてから** 中身を作る（粒子がワールド座標で出るため）。
5. `vfx_lab.gd` の `ITEMS` と `play()` に足し、`tests/vfxtest.gd` に出現と片付けの確認を足す。

## 確かめ方

```bash
GD=./tools/godot/Godot_v4.7.2-stable_win64_console.exe
# コマ並べ画像（各8コマ）を godot/tests/shots/vfx_review/ に書き出す。--only=<id> で1つだけ
$GD --path godot --fixed-fps 60 res://vfx_lab.tscn -- --shots
$GD --path godot --fixed-fps 60 res://vfx_lab.tscn -- --shots --only=explosion
# 走りの演出
$GD --path godot --fixed-fps 60 --script res://tests/runfxshot.gd
# 出現と片付けの自動確認（画面なし）
$GD --headless --path godot --script res://tests/vfxtest.gd
```

- 画面つきの実行は、数秒だけユーザーのデスクトップに窓が出る。
- 出力に `SHADER ERROR` や `ERROR:` が無いことを見る。その後、書き出した PNG を**必ず開いて見る**。
- **終わりの0.5秒を、細かいコマ割りで別に見る。** 8コマの一覧では終わりが1コマしか写らず、見落とす。人が一番気にするのは「最後に出る変なもの」
  （砕けた破片、点々の火の粉、宙に残る塊）。ノイズで穴を開けて消す・粒に砕く、は手軽だが、形として設計していないと必ずゴミに見える。
  消え方も「何に変わって、どこへ行くか」を決めて振り付ける。
- 部品が揃っているかの点検で終わらせない。全コマを通して「一番目につく変なところはどこか」を先に探し、それを指摘の先頭に置く。
- 見るところ：最初の数コマで何が起きたか分かるか／形が塊として読めるか／人（1.7mの円柱）に対して大きさが合うか／
  撮影カメラの明るさ（`*_film.png`）でも飛びすぎ・沈みすぎがないか／最後に何も残らないか。
- 人が眺める時は `play_vfx.bat`（←→で切り替え、P で停止、スロー、撮影カメラの明るさ切り替え）。

## 絵柄に合わせる（一度「死ぬほどダサい」と言われて作り直した教訓）

このゲームはぬいぐるみ調のコメディ。走りの演出を最初、水色の半透明コピー・定規で引いたような光の帯・真円の輪で作り、全部ボツになった。

- **ネオンSFを載せない。** キャラと無関係な色の発光体は、絵柄と喧嘩する。キャラ自身の色（スミア）、題材のある現象（雷）を使う。
- **機械的にまっすぐ・均一にしない。** 太さ・長さ・位置を不揃いにし、両端を細らせる。
- **コマ打ちを素材に合わせる。** 漫画の衝撃・決め絵は12〜15コマ/秒も使う。気体・液体・プラズマの流れまで低fpsへ固定しない。滑らかな移流と短い衝撃の拍を使い分ける。
- **ばらばらのノイズにしない。** 頂点ごとの乱数で伸ばすと「映像の乱れ」に見える。高さごとの帯など、まとまった形で動かす。
- **走者から離さない。** 置き去りにする線や跡は、速い走者だとすぐ画面の外へ行く。走者について行かせる。
- 稲妻は点を間引いて交互に振る。細かい乱数の揺れは「もつれた落書き」になる。
- **線を一本引いて終わりにしない。持っている型を使う。** 雷の疾走は最初、稲妻の線を引いただけで「飛び道具の感じを出せばいいのに」と言われた。
  動くものに付ける演出は、走者や物体を「飛び道具の頭」と見立て、発射・頭（オーラ／光／這う放電）・軌跡・補助（粒／輪）・終わり、を全部そろえる（`vfx_run_thunder.gd`）。
  色も `vfx_projectile.gd` の `PALETTES` を共有する。
- **スミアは「引き伸ばし」だけでは表現が足りない。** 体の速度で後ろへ伸ばすだけだと手足の動きが出ない。少し前のポーズの写し（マルチプル）を重ね、
  薄さは半透明ではなく網点（スクリーントーン）で出す（`vfx_run_smear.gd`：骨格の写しに過去のポーズを流し込む）。
  伸びた先は尖らせ（`sharpness`）、色を変えて輪郭を立てる（`edge_color` / `tip_color`）。
- **うまくいった演出同士は掛け合わせられるように作る。** 好評だったのは単体より掛け合わせだった。部品を切り替える変数を持たせておくと、新しい演出が20行で作れる。
  - `vfx_run_volt.gd`：スミア（`electric` で先が雷の色・折れ線）＋ 雷（`bare` でオーラと帯なし）
  - `vfx_run_gale.gd`：スミア ＋ 風の線（`vfx_run_wind.gd`。光らない白い曲線）
- **色違いの使い回しで済ませない。** スミアに添える白い線を、最初は雷の線を白くまっすぐにして作り、「雷っぽくなく、曲線的で、光ってない感じに」と直された。
  題材が違えば形と質感から変える：風は弧（ベジェ曲線）で、加算ではなく普通の塗り（`stroke` シェーダー、色はグローの閾値 1.6 より下）、先頭から描いて先頭から消す。
- **線は一種類で終わらせない。** 稲妻が等間隔の折れ線一本だと「単調」と言われた。折れ点の間隔と振れ幅を不揃いにし、大きな折れに小さな震えを重ね、
  数コマに一度太く光り直し、枝と影の一本を出したり消したりする。
- **形を見せたい時は、粒子を乱数でばらまかず、ひとつずつ振り付ける。** 蹴り上げの土ぼこり（`vfx_run_dust.gd`）は最初 GPU 粒子で作り、小さな塊が3つ散るだけで貧相だった。
  「いつ・どこへ・どの大きさで」を表（`KICK` / `STEP`）に書き、MultiMesh で1体ずつ置くと、順に弾ける・尾を引いて巻き上がる、といった形が設計できる。
  MultiMesh なら伸び縮み（進む向きに伸ばし、止まると丸く戻す）もでき、`cloud` シェーダーは粒子と同じく色のアルファで溶ける。
- **キャラの体の一部を増やす・回す、もVFXの範囲。** 脚ぐるぐる（`vfx_run_wheel.gd`）は、スミアと同じ「骨格の写しに過去のポーズを流し込む」を使い、
  写しをいまの場所に置いて、走りの一周ぶんの違う瞬間の脚を重ねたもの。腰より上は `smear` シェーダーの `cut_above` で描かない。
  腕は腰の高さまで下がって混ざるので、写し側で腕の骨を縮めて消す（骨の名前 `UPPER_ARM` に依存）。
- **トゥーンの塊には輪郭線を付ける。** `cloud` の材質の `next_pass` に `cloud_ink` を付けるだけでよい。
- 漫画風の白いスピード線だけを単体で出す演出は「いらない」と言われて削除した。線はスミアや雷に添える形なら受け入れられた。

## 流れを先に作る（素材名を付けた拡縮だけで済ませない）

形・歪み・流れのテクスチャを設計する時は [資料からの素材設計](references/material-reference.md) も読む。ユーザー提供字幕とLeLu/Simonの資料、今回使ったチャンネル分離をまとめている。

**再現依頼の骨格を失わない。** 動画に近づける依頼で「流れを改善して」と指摘されても、元の主塊・色の面積・層の発生順・膨張と崩壊の拍を保持する。今回、厚い白熱火球・火柱・炎輪の参考を、薄い布状の炎と上昇煙に置き換えた密度場の試作はユーザーに拒否された。技法の実験へ目的をすり替えた失敗であり、動画の再現結果として扱わない。参考と出力の発生・最大形・崩壊を並べ、まず構造と拍の一致を判断する。

煙・炎・プラズマ・液体は、完成形の個体に移動とscaleを付けても、その素材の運動にはならない。
**圧力や供給源→噴出する先頭→後部が追いかける→巻き返し・せん断・分岐→供給停止後の流出** をまず主役の形で作る。
消え方だけを3種類に替えても、途中が静的な房・コーンの拡縮なら3案とも同じ失敗になる。

- 各地点を通過する速さと向きを変える。ノード全体の位置とscaleだけではなく、中心線の曲率、局所幅、密度、首の位置、分岐点を流れに従わせる。
- 気体を密度場・渦で動かす時は、物質を速度場で移流し、合流と巻き返しが外形に現れるようにする。静的な球の表面に流れる模様を貼るだけでは不十分。
- テンポは不等速にする。短い噴出、少し遅れる追従、大きい巻き返し、勢いが抜ける余韻を同じeaseで均すな。
- 色を隠しても流れが読める段階を先に作る。表面のノイズ、光、細かな火花はその後に加える。
- **通常速度で途中を先に見る。** 「穴がない」「最後に片付く」「曲線や房がある」は合格理由にならない。主塊が固いまま縮む、浮いた房がscaleだけで縮む、コーンが規則的に並ぶ時は流れから作り直す。
- 密度サンプルを移流しても、離れた丸いkernelが見えるだけなら「丸い粒が飛ぶ」まま。連続した流路でつなぐ、密度の巻き返しで外形を折るなど、合流とせん断を画面で読めるようにする。技法名は品質の証拠にならない。
- 12〜15fpsはコマ打ちの衝撃や決め絵の選択肢。ユーザーが滑らかな素材の流れを求める時は移流・尾・局所変形を24〜60fpsで進め、全体を低fpsに固定しない。

### 好評の飛び道具を参照する（細い白い発光線で代用しない）

ユーザーは `vfx_projectile.gd` の飛び道具を好評とし、新しい爆発の細長い線状パーティクルを拒否した。
既存の `shot_fire.png` 等を開き、**白熱する頭・色のあるオーラ・幅のある短い尾・こぼれる粒** が作る面積と流れを見てから作る。
細い白芯のRibbonを何本か添えるだけでは参考にしたことにならない。小さな飛散物でも先頭が読め、尾は過去の軌道を追い、減速で短くなり、冷却で色が落ちること。
`orb`/`ribbon` を使う場合、既存のTIME駆動を一時停止対応VFXへそのまま持ち込まず、ageから位相を渡す。ノイズで穴を開ける層の上限は、頭と尾も含めて数える。

**飛び道具の構成を、小さい火花へ丸ごと縮めない。** 白いSphere芯＋丸いオーラを最後まで残した7個の火花は、飛ぶ発光物体に見え、ユーザーに「個体っぽさがすごい」と指摘された。火花が熱や気体の裂片なら、前方の高温部は役割であって、独立した球ノードではない。

- 固い粒を飛ばす表現と、短時間に噴いた材料の流れを分ける。後者は `sample_age = 現在時刻 - 放出時刻` で各部分を動かし、放出中の方向・速さの変化から伸び・せん断・曲がりを作る。同じ物体の履歴をつなぐだけでは個体の尾になる。
- 明るい腹・左右の肩・首を別々に動かす。白熱は短く、幅や輝度の最大位置を頭へ固定しない。
- 先行する短い裂片、遅れる幅広の流れ、腹から剥がれる枝に、供給時間と冷却時間の差を付ける。同形の粒が一斉に落下して終わらない。
- 球を廃止しても長い均一な弧なら布リボンに見える。供給停止後は細い尾を腹より先に失わせ、短い幅広の熱片として読む面積を保つ。
- `vfx_ember_stream.gd` はこの指摘に対する新しい実装。旧版と同一視点で単体・本体との統合を描画し、見た目はユーザー評価待ちとして記録する。

## 消え方は素材ごとに変える（「全部ノイズの穴で消える」の禁止）

`cloud` シェーダーの「色のアルファを下げるとノイズの穴が開く」は手軽なので、放っておくと煙も炎も土煙も全部これで消えてしまう。ユーザーに指摘された。
**ノイズの穴で消してよいのは、1つのエフェクトにつき1層まで。** 残りは下から選ぶか、参考元の消え方を真似る。作る前に「何が、何に変わって、どこへ行くか」を1行で書く。

| 素材 | 消え方の例 |
|---|---|
| 煙 | 上へ流れながら細く引き伸ばされて薄れる／小さな房に分かれ、1つずつ順に縮む／渦を巻いて中心へ縮む（『風のタクト』）／平たく広がって地面や天井を這う |
| 炎 | 舌が根元からちぎれ、上へ昇りながら細って消える／先が絞られて一筋になり、火の粉に変わる／色が白→黄→橙→赤と冷め、根元へ縮む／コマ打ちで2〜3回またたいて消える |
| 爆発 | 火球が煙に変わり、柱になって昇りながら上から薄れる／膨らみきって画面を覆い、白や黒へ飛ばして切る |
| 土煙 | 蹴られた向きへ流れて平たくなり、地面に落ちる／房が弾けて縮む |
| 光・雷 | 明滅しながら細る／光り直して一瞬で消える（余韻は別の層に任せる） |

確認のときは、終わりの0.5秒だけを細かいコマ割りで見て、「最後に目につくのは何か」を言葉にする。それが破片・点々・宙に浮く塊なら作り直す。

### 実装前に層ごとの出口を記入する

層ごとに **素材／消え始める時刻／形が何へ変わるか／流れる方向／次に残るもの** を短い表にする。
「縮小してフェード」だけでは出口の設計にならない。例えば煙なら、上昇で首が細くなる→房同士が離れる→最後の房が上へ抜ける、という順序まで決める。

- ノイズ穴の予算は、シェーダーの数ではなく**画面に重なる意味のある層**で数える。同じ `cloud` を使っても、火球・火柱・地面の房は別の層。
- `cloud` の `COLOR.a` を下げると穴が開く。穴を使わない房は `COLOR.a = 1` に保ち、移動・変形・房ごとの時差・通常の薄れで終える。通常の薄れには専用の材質を用意する。
- 炎の舌がちぎれる時は、切れ目と根元を先に変え、離れた舌が上昇する。元の位置のまま全体のscaleを下げるだけでは、ちぎれたことにならない。
- 圧力の輪は外へ進み続けながら断面を薄くするか、弧の先端から消す。煙と同じ穴のパターンを重ねない。
- 複数案を出す時は、同じカメラ・露出・発火時刻で比較し、終わりだけの細かいコマも添える。未評価の案を「好評だった型」としてスキルへ固定しない。

### 火花はパーツではなく飛ぶ物質として作る

まず `vfx_explosion.gd` の火花を描画して見る。良い手掛かりは **初速→減速→重力で軌道が曲がる→白黄橙赤へ冷める** という因果と、速度に沿った細い筋。
剛体のコーンや棒を年齢で拡縮し、位置を移すだけの火花は作らない。

- 位置は初速・抵抗・重力から決める。向きは固定の放射方向ではなく、その瞬間の速度に従わせる。
- 尾を使うなら、飛ぶ頭の**少し前の位置**を数点つなぐ。頭と尾が同じ経路を通り、曲率と実速度が輪郭に現れる。軌道と無関係な長い棒を頭に付けない。
- 尾の長さは短い時間幅と速度で決め、止まると短くなる。縮小は熱や速度が失われた結果として使う。全パーツが同じ縮小曲線で終わる作りにしない。
- 生まれた直後・弧の頂点・落下中を比較する。先端の方向、尾の曲がり、長さが軌道と合い、最後に大きな三角片や等間隔の棒が残らないことを見る。
- 火花の途中のscaleは副次的な補助。scaleを固定しても、軌道・輪郭・冷却だけで飛ぶ物質に見える状態を先に作る。

## 色と明るさ

- 色はリニアで書く。シェーダーの色に `source_color` は付けていないので、数値がそのまま出る。
- 1 を超える値でグローに乗る。目安：白熱 8〜10、炎の橙 `(5, 1.3, 0.15)`、煤 0.2〜0.3。
- 現場（`stage.gd`）は白飛び点 6・グロー閾値 1.6、撮影カメラ（`film_camera.gd`）は露出 0.28・閾値 2.2。
  両方で見る。Motion Lab と VFX Lab も現場と同じトーンマップ・グローにしてある。

## はまりどころ（実際に踏んだもの）

- **泡ノイズで雲の形を作らない。** 球を泡ノイズで押し出すと「穴だらけの岩」に見えた。丸い房の重ね合わせ（`cloud_mesh`）にする。
- **溶かしの穴が最初から開く。** 泡ノイズは 0 付近の値が多い。`cloud` シェーダーは値を底上げしてあるので、色のアルファは溶かし始めるまで 1 に保つ。
- **大きな閃光が床で切れてドームに見える。** `glow` の `toward_camera` で手前へ寄せる（見かけの大きさは保たれる）。
- **輪は内側まで塗らない。** `ring_width` が太く明るいと、輪ではなく白い円盤に見える。
- **大きさ 0 にしない。** 変化の始点は `lerpf(小さい値, ...)` にする。
- **不透明な雲の中に別の雲を入れても見えない。** 「芯」を見せたい時は加算の板を重ねる。
- **`Lib.process()` の項目名を間違えると assert で止まる**（黙って無視されないようにしてある）。放射方向の速度は減衰（damping）が効かないので `radial_velocity_curve` で減速させる。
- **帯（Ribbon）は `top_level`。** 点はワールド座標で渡す。同じ点を続けて入れない。
- **動くキャラをもう一度描きたい時は、同じ `mesh`・`skin`・`skeleton` を持つ MeshInstance3D を横に足す**（`vfx_run_smear.gd`）。ポーズの焼き込み（`bake_mesh_from_current_skeleton_pose`）は画面なしで失敗し、毎フレームやるには重い。
- **ノードに予約した関数の中で `queue_free()` した直後も、そのフレームは触れる。** 片付けは変化の終わりより 0.01 秒後に予約する。
- 外部のテクスチャ素材を使う時は、取得元とライセンスを `godot/assets/vfx/<名前>/SOURCE.md` に残す（Kenney の煙が例）。
  差し替えは材質に `set_shader_parameter("flame_texture", 画像)` などで渡すだけでよい。

## 作品の作風に寄せたエフェクト

| エフェクト | 呼び出し | 要点 |
|---|---|---|
| インク `vfx_ink.gd`（スプラトゥーン風） | `spawn(parent, ground, "splash"/"bomb"/"tornado", size, "orange"/"blue"/"pink"/"green")` | 光らせない。濃い色・暗いふち・白い照り（`ink` シェーダー）。滴は1つずつ放物線で飛ばし、落ちた所に水たまり（`splat`）。乾くときはふちが外から中心へ引く。コマ打ちにしない |
| 呪力 `vfx_cursed.gd`（呪術廻戦風） | `spawn(parent, pos, "black_flash"/"blue"/"purple", size, direction)` | 15コマ/秒。当たりは1コマ単位で絵を切り替える（白 → 黒に赤ふち）。黒い稲妻は塗り（`bolt_dark`）なので黒が沈まない。球は SphereMesh ＋ `flow` |

- **「メッシュ＋流れる絵をくっきり切り抜く」**（竜巻・球・殻）は `flow` シェーダーで足りる。筒は `Lib.tube_mesh`、球は SphereMesh（UV.y は上が0なので `eaten` は上から裂ける）。色の4段を「暗い地色〜明るい照り」にすればインクにも呪力にもなる。

- **水たまりのふちに細かいノイズを使わない。** 粒々でざらついて、液体に見えなくなる。大きくなめらかなうねり（低い周波数）にする。
- **黒を見せたいものは加算で描かない。** 加算は黒が透明になる。塗りで描き、ふちだけ強い色で光らせる。

## 安っぽく・固体っぽく見せない（ユーザーの読み解きから。インク6種・呪力6種を「めちゃくちゃ微妙。固体感がすごい。安っぽい」と言われた）

ユーザーは、薄い低密度層を重ね外から中心へ明度を上げ、根元を別プロセスで動かし、地面模様を複数合成して時間差で消すプロンプトで「うまくいった」と明示した。**成功した構成として引き継ぐ。** 層を使うこと自体を固体感の原因として禁止しない。各層の疎密・前後の流れ・明度・部位ごとの運動が、画面で立体感を作るかを見る。

明度と密度は別の制御にする。内側を明るくするために外側まで高密度にすると、奥が隠れて殻へ戻る。流れにある恒常的な空隙・筋のマスクと、寿命でランダムな穴を増やす消去も区別する。薄い層が複数あっても、終了のノイズ穴消しは全体で1層まで。

原因は「密度の高い殻を1枚だけ置いて、その中を色分けした」こと。塗った円錐・塗った球に見える。作り直した見本は `vfx_tornado.gd`（`wisp` シェーダー）。

- **何層にも重ねる。1層ごとの密度は低く。** 同じ軸の殻を5層ほど、どれもすき間だらけにする。奥の層がすき間から見えて、はじめて奥行きが出る。
- **外から中心へ明るくする。** 外は暗い色、中心ほど明るく。1層は1色（＋明るい筋）にとどめ、1枚の中で4段に塗り分けない。
- **層ごとに動きを変える。** 回る速さ・昇る速さ・絵のずらしを層ごとに変える。うねり（`sway`）だけは全層で同じにして軸を揃える。
- **根元は別の仕組みで動かす。** 本体と逆回りの太く詰まった帯、脈打つ動き、地面すれすれの跳ね。本体の延長で済ませない。
- **地面の模様は1枚置かない。** 大きさ・向き・速さ・色の違う模様を数枚重ねて、1つの模様に見せる。
- **出入りの時刻をずらす。** 芯から立ち上がり、外側から順に消える。地面の模様も1枚ずつ遅れて閉じる。全部が同時に消えると「急に消えた」になる。
- **絵は大きく太い塊で。** 細い縦筋ばかりだと花火や噴水に見える。絵の拡大率を下げ、斜めに倒して帯にする。
- **平たい光の円盤を背景に置かない。** にじみ（グロー）に任せる。薄い光の板は丸い膜に見える。
- **筒の上端を平らに見切れさせない。** メッシュのふちでスパッと終わると安っぽい（ユーザー指摘）。`wisp` の `tip` で角度ごとに高さの違う舌にし、`top_thin` で先ほどまばらにし、層ごとに高さを変える（外は低く、芯が突き出る）。欠きすぎると炎に見えるので、竜巻は 0.17 くらい。球や板では `tip` を 0 にする。
- **地面の模様を「円が縮んで消える」にしない**（ユーザー指摘）。重ねた1枚ごとに別の消え方を、時刻をずらして使う：`cut` を上げて腕を細らせ千切る／`sweep` でぐるっと一周ぬぐう／広げながら薄れさせる／中心へ吸い込む。
- **球の芯は一番明るく。** 暗い芯のまわりに暗い殻を重ねると、ただの暗い玉になる。
- **地面の帯は、ふちもぎざぎざに。** 模様だけ入れてもふちが直線だと絨毯に見える（`wisp` の `side_ragged`）。
- 層を重ねる殻は `Lib.wisp_layer(mesh, 番号, 層の数, 色, 明るい色, 追加の設定)` で作る。
- **作品風のものは、その作品の「一番の特徴」を先に言葉にしてから作る。** 黒閃とインクは部品を並べただけで「ださい」と言われた。作り直しで入れたもの：
  - 黒閃：当たった瞬間に画面ごと白黒反転する2コマ（`invert` シェーダー。画面を覆う板で、`render_priority` を低くして先に描き、稲妻はその上に黒で乗せる）。稲妻は細い根のように散らさず、太く角ばったものを数本、殴った向きへ。
  - インク：空中は模様を貼った殻ではなく、艶のある丸い塊（大・中・細い筋の3種類を速さを変えて）。水たまりは平たい色面にせず、ふちの盛り上がりを光の側は白く・影の側は暗く塗り、腕を数本だけ伸ばす（`splat`）。小さな滴の跡は腕を弱めて丸く保つ。
- **`depth_draw_never` や `depth_test_disabled` の材質は、不透明でも半透明の順番で描かれる。** 画面を読むシェーダー（`hint_screen_texture`）にはそれらが写らないので、重ね順は `render_priority` で決める。
- **「〇〇＝この絵」という固定観念で、板に貼った絵と線だけで済ませない**（ユーザー指摘：「イラストに引っ張られすぎ。薄い層のシェーダーを重ねて立体的に表現できていない」）。黒閃を「黒い稲妻の絵」と決めつけて平面で作り、2度ださいと言われた。
  立体の本体を先に作る：殻を重ねた塊（外は黒、内へ赤、芯は白熱）、向きのある噴流（同じ重ね方の円錐）、芯を通る光線、光を受けた煙の塊。絵（衝撃マークなど）や線（稲妻）は、その上に添えるものとして最後に足す。
- **黒いものに色の光を落とす**：`cloud` シェーダーで、影の色を黒、塊の色を暗い色、照り返しを強い色にし、`light_dir` を下向きにすると「下から照らされた黒い煙」になる。黒い殻のすき間から内側の明るい層を漏らすのも同じ効果。
- **指摘は、言われた部品そのものを直す。** 「黒閃を改善」「薄い層を重ねて」と言われて、稲妻を放置したまま黒い炎の塊や噴流を足したら「黒閃じゃなくなった」と言われた。指摘の対象は稲妻だった（「固形の折れ曲がった棒がちらついて瞬間移動しているだけ」）。何を直すのか曖昧なら、盛る前に対象を確かめる。
- **稲妻・光線を固い棒にしない**（`vfx_cursed.gd` の黒閃、`bolt_flame` シェーダー）：
  - 1本を層で作る：にじみ（加算・広い）→ 燃えるふち → 本体 → 芯（加算・細い・またたく）。同じ道筋に幅と色と流れる速さを変えて重ねる。
  - ふちを、根元から先へ流れるノイズで欠く。左右で別の模様にして対称にしない。先端もちぎれて終わらせる。
  - 毎コマ別の形へ跳ばさない。折れの形は保ったまま、点を sin でゆっくりうねらせる（先ほど大きく）。根元から伸ばし、形が変わるのは「光り直し」の1回だけ。稲妻だけは毎フレーム動かす。
  - 黒を見せたいなら、赤の層を強くしすぎない。にじみ（グロー）が黒い本体を塗りつぶす。

## 稲妻の作り方（黒閃を3回作り直して、調べ直して分かったこと）

**稲妻を「折れ点を結んだ帯」で作らない。** 何層重ねても、ふちを欠いても、うねらせても「固形の折れ曲がった棒」に見える（ユーザーに3回言われた）。ゲームの稲妻は、平らな板の上で、流れるノイズから線を取り出して描く。

- 作ったもの：`arc` シェーダーと `vfx_black_flash.gd`。帯は始点と終点の2点だけ渡し、板の中でシェーダーが線を描く。
  - 線の位置：`中心 = ノイズ(根元からの距離 − 時刻×速さ)` でずらす。大きなうねりに細かい震えを重ねる。根元は動かさない。
  - 枝：途中のある位置から、別のノイズで本流を離れていく線を足す（距離の最小を取る）。本流より細く、先に尽きる。
  - 動き：ノイズが先端へ流れ、形そのものもゆっくり変わる。跳ぶのは `seed` を変える「光り直し」のときだけ。
  - 断面：線の中心からの距離で、芯 → ふち → にじみ、と塗る。層を別の帯にしなくてよい。
  - 放電の網（`web = true`）：ノイズが 0.5 をまたぐ所だけを線にする。放射状の板の上を細い線が這う。
- **黒い光は乗算済みアルファで描く**（`blend_premul_alpha`）。芯は「色0・アルファ1」で背景を隠し、にじみは「色あり・アルファ0」で足し算になる。加算だけでは黒は出ない。
- **黒を見せるなら、芯を太く（線の7割）、赤は弱く。** 赤が強いとにじみが黒を塗りつぶす。くねりの細かさ（`frequency`）を上げすぎると、細かい落書きになる。
- 参考：realtimevfx.com「Noise-based lightning shader like in Zelda?」、godotshaders.com「2D Lightning, Electric Arc, plasma」。手描きアニメの稲妻は毎コマ描き直すが、形はゆるく不揃いで枝があり、先へ細る。
- **行き詰まったら、盛り直す前に作り方を調べる。** 見た目の調整を3回やっても直らないときは、前提（ここでは形の作り方）が違っている。

## Pixel × Real パック（`godot/pixel_vfx/`）

`vfx/` とは別の独立したフォルダ。ドット絵の絵柄を 3D の光の中に置く。使い方と絵柄の決まりは `godot/pixel_vfx/README.md`。

- 絵は画像ではなくシェーダーで描く：UV をマスに丸める → 5 色の段に落とす → 境目は市松ディザ → 隣のマスを見て輪郭
- 12 コマ/秒で `_step(t)` を呼ぶ。模様の `phase` も位置も同じコマで送る（片方だけ滑らかにしない）
- 立方体は `put()` でマス目の位置にだけ置く。光る強さは INSTANCE_CUSTOM.x（頂点で varying に渡す）
- 消え方はフェード禁止。`fill` や `close` でマス・区画・列が点滅して欠ける
- 新しいものを足すときも `vfx/` の部品は呼ばない（フォルダごと配れる状態を保つ）
- 確認は `--script res://tests/pxtest.gd` と、ラボの `px_flame` `px_burst` `px_portal` `px_teleport`

## 黒い稲妻の試作（`vfx_black_bolt.gd`、ラボ id `black_bolt`）

すき間のある筒 3 層を折れ線の節ごとに並べ、15 コマ/秒で折れ点を小さく震わせる案。静止画では「模様のついた棒の束」に見え、固体感は消えていない。
節の継ぎ目が見えること、太さが節ごとに一定なことが原因と見ている。採用はしていない。
