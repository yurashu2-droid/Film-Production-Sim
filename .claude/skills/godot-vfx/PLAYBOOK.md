# VFX 作業手順書（この順に進める。飛ばさない）

SKILL.md は辞書、このファイルは手順。迷ったらこちらに従う。
ここにある規則は、2026-10-08 に水の演出5種を作って「固体に見える」「動きを見ていない」と指摘された失敗から作った。

## 0. 依頼主が求める見た目（これが合格基準）

1. **固体に見えない。** 気体・液体・炎・電気は、殻のすき間から奥の層が見える。
2. **見える奥行き。** 薄くてすき間のある層を重ね、前後の流れを見せる。三層は体積表現の有効な出発点で、全素材の固定レシピや演出量の採点ではない。発光体は外を暗く内を明るくする。墨・砂・非発光の煙へ白い芯を強制しない。
3. **流れる。** 模様が流れるだけでは足りない。形そのもの（中心線・太さ・先端）が時間で変わる。
4. **終わりが汚くない。** 宙に残る塊、縮むだけの円、同じノイズの穴で全部消える、は不合格。

## 0.5 消え方は主役（依頼主の強い要望。出来の半分は終わりで決まる）

「宙に残らない」だけでは合格にならない。**その演出の素材・生き物・動きにふさわしい消え方**を、最初に設計して作る。

1. 作る前に1行で答える：「この演出は何でできていて、それはどう終わる物か」。
   - 墨の龍 → 外の墨がほつれ、金の脈が先に抜け、墨が滴って地面に染み、染みが乾く
   - 水 → 流れ落ちて水たまりに戻り、波紋が残って静まる
   - 炎 → 先から千切れて昇り、火の粉と煙に変わる
   - 雷・電気 → 接続点から先へ伝播し、遅れた枝が放電を受け渡して消える
   - 氷・結晶 → ひびが走って砕け、破片が落ちる
2. 層ごとに違う終わり方・違う時刻にする（外が先にほつれる、芯が最後に抜ける、など）。全層が同じ瞬間に同じ消え方なら不合格。
3. 消える物は**どこかへ行く**。縮んで消える・ノイズの穴で消える・フェードだけ、は禁止。地面へ落ちる、上へ抜ける、別の物（染み・煙・波紋）に変わる、のどれかにする。
4. 地面の陣・輪・光も、本体とは別の終わり方を持たせる（色が沈む、外から欠ける、など）。
4.4. **光線・稲妻・帯・柱を、先端から根元へ引き戻して消さない**（`grow` を下げて「元の場所へ戻る」のは禁止）。「本当にそう消える？」と見た人が引っかかる。電気や光は、供給が止まって**根元から先へ消える**（`eaten`）か、先端側が進んできた向きへ少し進んで千切れる。外の層が先、芯が最後。戻してよいのは、巻き取る・縮む性質の物（触手、舌、ロープ）だけで、その理由を先頭コメントに書く。
4.5. **`stamp` の `hide` は使わない。** 外から中心へ円が狭まるだけで、縮んで消えるのと同じに見える（それまで回っていた意味も消える）。地面の陣・輪は、回転を止めずに `sweep`（扇形にぬぐう。`sweep_from` で始点）と `cut`（模様がちぎれる）で消す。輪が2枚以上なら、始点と時刻をずらす。
5. (c) の終わりの画像で、**1コマごとに何が何に変わったか**を言葉で説明できなければ不合格。説明が「薄くなった」だけなら作り直す。

見本：`godot/vfx/vfx_ink_dragon.gd` の `_pose`（層ごとの starts/ends、墨のしずく、陣の染み）。

## 1. 使ってよい物・使ってはいけない物

太さ・大きさの数値は、依頼書に具体的な値があれば依頼書に従う（脇役の細い筋など、わざと細くしている場合がある）。
層の数は、この手順書と依頼書が食い違ったら**多い方**に従う（主役は3層以上。細い脇役は2層でもよい）。

| 表したい物 | 使う | 使わない（固体に見えた実績あり） |
|---|---|---|
| 水・炎・気・煙の体 | `Lib.wisp_layer()` を3層以上 | `SphereMesh` `CylinderMesh` `BoxMesh` に材質を1枚貼る |
| 曲がる体（波・蛇・鞭・稲妻） | `Lib.path_tube(Lib.smooth_path(点), 半径)` を毎コマ作り直す | 短い筒を節ごとに並べる（継ぎ目が見えて骨に見える） |
| 丸い塊（玉・泡） | 球メッシュに `wisp` を3層、層ごとに回る向きを変える | `water_ball` シェーダーの球1個、`Lib.cloud_mesh` の塊 |
| 帯・弧 | 細い `path_tube` を3層、または `Ribbon` を太さ違いで3本以上＋内側に流れる層 | `stroke` の帯1〜3本だけ（べた塗りの板に見える） |
| 地面の模様 | `stamp` を2〜3枚、回転と消える時刻をずらす | 1枚を縮めて消す |
| 小さな粒（水滴・火の粉） | MultiMesh。直径 0.15m 以下なら単純な球でよい | 大きな粒を単純な球で出す |

氷・岩・破片のように**本当に固体の物**は、依頼に「固体感なし」とある時は題材ごと変える（例：氷柱 → 流れる冷気）。勝手に固体で作らない。

### wisp の色は必ずこう渡す

```gdscript
# [暗い色, 明るい色, cut, inner]  外 → 内
const LAYERS := [
	[Vector3(0.04, 0.22, 0.9), Vector3(0.12, 0.55, 1.5), 0.70, 0.50],   # 外：すき間が多く、ほぼ暗い色
	[Vector3(0.18, 0.70, 2.0), Vector3(0.70, 2.20, 3.4), 0.60, 0.30],   # 中
	[Vector3(0.90, 2.20, 3.0), Vector3(3.00, 4.40, 4.8), 0.50, 0.14],   # 芯：詰まっていて白い
]
```

- `cut` を上げる＝すき間が増える。外の層ほど大きく。
- 筒や球が「べた塗りの束」に見えたら、すき間が足りない。外の層の `cut` を 0.05 ずつ上げ（0.80 まで）、同時に内の層の半径を小さくして、外のすき間から内の層が見える状態にする。寄りの画像で、外の層の面積の3〜4割がすき間になるのが目安。
- `inner` を上げる＝明るい色で塗る面積が減る。**外の層で `inner` を既定(0.14)のままにすると全部白くなり、層が見えなくなる。**
- 内の層ほど半径を小さく（外 1.0 / 中 0.65 / 芯 0.3 が目安）。同じ半径で重ねると1枚に見える。
- 筒を太くすると模様も粗くなる。半径を上げたら `scale_a` の周方向（x）も同じ割合で上げる（半径 0.3 → 0.7 なら x を 1.0 → 2.5）。
- **筒は太く作る。** 外の層の半径が 0.5m より細いと、殻の模様が読めず「刃」「棒」「結晶」に見える。柱・腕・舌は外の半径 0.7〜1.2m、芯でも 0.2m 以上。細い線が欲しい時だけ `Ribbon`＋`stroke` を1〜2本添える。
- 霧・冷気・湯気を wisp の淡い色だけで作らない（試して失敗：白っぽい平たい板・割れた氷の破片に見えた）。wisp は縁がくっきり切れるので、明暗の差が無いと板になる。霧の体は煙玉（下の「煙玉の使い方」）で作り、wisp は暗い青〜白の差をつけた細い筋を2〜3本、芯として添えるだけにする。
- 球・板に貼る時は `"tip": 0.0, "sway": 0.0`。
- 外の層が「平たい破片」「地図の大陸」に見えたら、模様が大きすぎる。`"scale_a": Vector2(3.0, 0.6)` のように周方向を細かくし、`shear` を 1.0 前後にして、斜めに流れる筋にする。
- `cut` を寿命に応じて上げる穴消しは、エフェクト全体で意味のある1層まで。採用するその層では閾値を値域の上限より大きくして最輝点まで消し切る（既存wispでは1.05）。残りの層は移流・落水・上昇・房の分離など、素材別の出口を持つ。全層の `cut` を上げて終わらせない。

### 煙玉の使い方（`vfx_toon_puffs.gd`。霧・湯気・土煙・しぶきの煙）

```gdscript
const Puffs := preload("res://vfx/vfx_toon_puffs.gd")
# plan の1行 = 煙玉1個：[遅れ(秒), 向き(Vector3), 進む距離(m), 大きさ(m), 寿命(秒)]
var plan: Array = []
for i in 14:
	var a := i * 2.4
	plan.append([0.2 + i * 0.12, Vector3(cos(a) * 0.3, 1.0, sin(a) * 0.3), 1.2, randf_range(0.7, 1.2), 1.6])
var mist: Node3D = Puffs.new()
add_child(mist)
mist.rise = 1.2                                    # start の前に。上へ流れ続ける速さ
mist.start(plan, _size, Color.WHITE)
mist.recolor(Vector3(1.25, 1.4, 1.5), Vector3(0.6, 0.78, 0.95), Vector3(0.2, 0.35, 0.55))   # 明るい面, 影の面, 輪郭線
```

- 動き：出てから 0.32 秒で「向き × 進む距離」だけ進んで止まり、その後は `rise` の速さで上へ流れ続ける。位置 = 向き×距離 + 上×rise×経過秒。
- 色：`tint` は掛け算。既定の塗りは土煙の暖色なので、青白くしたい時は必ず `recolor()`。
- 消え方：寿命の後半で、連番の絵が「丸 → 欠ける → 三日月 → 消える」。穴あきノイズではないので、他の層と消え方が重ならない。
- 1個は平たい板（カメラ向き）。**数を出して重ねる**（12〜24個）、大きさと遅れをばらつかせる。3個だけだと綿の塊に見える。
- `Puffs` は自分の `life` で消えるが、親のエフェクトより長く残さない（親の life − 0.6 秒までに寿命が終わる plan にする）。

## 2. 作る前に書く（コードの先頭コメントに残す）

```
素材：        （水 / 炎 / 冷気 …）
どこから来る： （地面の陣から湧く / 手元から伸びる …）
先に動く部分： （先端・頭）
遅れて追う部分：（尾・しぶき）
形の変化：     （中心線がこう曲がる、太さがこう変わる）を時刻つきで3つ以上
終わり：       層ごとに「何に変わって、どこへ行くか」。3層あれば3通り、時刻もずらす
```

「形の変化」が「大きくなる」「回る」だけなら設計不足。書き直す。

## 3. 時刻の決まり

- ラボの `ITEMS` は `[表示名, id, 繰り返しの間隔(秒), 撮る時刻(秒)の配列]`。**時刻は秒。割合ではない。**
- エフェクトの `life` は、ラボの `ITEMS` で最後に撮る時刻より 0.5 秒以上長くする。上限は 8 秒（`tests/watertest.gd` が 9.5 秒後に「消えたか」を見る）。
- 「終わり」の画像は、材料が供給停止してから最後の材料が流出する実際の区間を0.1秒前後で撮る。`life-1.2`〜`life-0.5`は候補で、既に空の時間を8枚並べても消え方の確認にはならない。
- 飛んでいる炎・雷・帯は発生元への巻き戻しで消さない。供給停止後も残りの材料を進行先へ流し、後端が先端へ追いつく。枝が本体から分かれた場合は、自分の速度・温度・重力に従う出口を持たせる。
- 分かれたしぶきや炎舌が本体より長く生きること自体は不具合ではない。動き続けて落水・冷却・上昇へ引き継がれるなら自然な余韻となる。静止した房や同形の棒が宙に残ることを直す。
- 終了時刻は素材と拍から決め、親の寿命は最後の材料の終了より後に置く。見せ場・分離物・床の順番を、全素材共通の固定秒数へ押し込まない。
- `path_tube` は点の列の最初が根元（UV.y=0）、最後が先端（UV.y=1）。進む物（弧・弾）は、尾を最初に、頭を最後に置く。

## 4. 確かめる（3種類の画像を全部見るまで「できた」と言わない）

```bash
GD=./tools/godot/Godot_v4.7.2-stable_win64_console.exe
# (a) 全体の流れ：8コマ → tests/shots/vfx_review/<id>.png
$GD --path godot --fixed-fps 60 res://vfx_lab.tscn -- --shots --only=<id> 2>&1 | grep -iE "error|VFX_SHOT"
# (b) 動き：見せ場を 0.1 秒おきに寄りで8コマ → <id>_flow.png
$GD --path godot --fixed-fps 60 res://vfx_lab.tscn -- --shots --only=<id> --dist=9 --times=2.0,2.1,2.2,2.3,2.4,2.5,2.6,2.7 2>&1 | grep -iE "error|VFX_SHOT"
# (c) 終わり：life の 1.2 秒前〜0.5 秒前を 0.1 秒おきに → <id>_end.png（life が 5.6 なら 4.4〜5.1）
$GD --path godot --fixed-fps 60 res://vfx_lab.tscn -- --shots --only=<id> --dist=9 --tag=end --times=4.4,4.5,4.6,4.7,4.8,4.9,5.0,5.1 2>&1 | grep -iE "error|VFX_SHOT"
```

通常のラボ撮影には `--fixed-fps 60` を付ける。`review_px50.gd`のように自動進行を止めてageを指定時刻まで進める撮影台は、その時計を使用する。出力30fps・素材の12fps・実際に採用されたフレーム時刻は区別して記録する。ラボの `ITEMS` に書く時刻は (a) 全体用。(b)(c) は `--times=` で指定する。
`error` が1行でも出たら、画像を見る前に直す。`--dist` は小さいほど寄る（既定は約14）。

### 画像を見て、次の問いに1つずつ答える（答えを報告に書く）

(a) 全体
1. 説明なしで、何が起きているか分かるか。
2. 使用場面と人（白い円柱＝1.7m）に対して占有範囲が合うか。接触の小さな演出まで人の数倍へ拡大しない。既定のゲーム距離で読めるかと、寄った時の形の確認を分ける。大・中・小の区分は下記の演出量で決め、メートルやカメラ距離で決めない。

(b) 動き：**隣り合うコマを見比べる**
3. 輪郭の形がコマごとに違うか。同じ輪郭で中の模様だけ違うなら「固定した殻」＝不合格。
4. 手前・奥・遅れて追う部位が見えるか。発光体の外側と明るい芯、非発光体の密度や色の差が読めるか。ノード数や三層という実装名だけでは判断しない。
5. すき間から奥が見えるか。べた塗りの面なら不合格。

(c) 終わり
6. 宙に切り離された塊がないか。
7. 全部が同じ瞬間に同じ消え方をしていないか。
8. 最後のコマに何も残っていないか。

1つでも不合格なら、直して (a) から撮り直す。**不合格が残っているのに1周で止めない。** 最低3周は直す。「不合格が多いので方針を決めてほしい」は止める理由にならない。不合格が多い時こそ、自分で原因を1つ決めて直し、撮って確かめる（原因の見立てが書けるなら、それを試すのが次の周）。止めてよいのは、依頼の文どうしが矛盾している時と、触ってはいけないファイルを変えないと進めない時だけ。3周しても残った不合格だけを、先頭に書いて報告する。
テストが失敗した時も同じ。原因を調べる（テストのファイルは読んでよい）。触れないファイルが原因なら、何行目をどう変えれば通るかまで書いて報告する。

### 画像の読み間違いを防ぐ

- 撮影台の白い円柱（人の高さ1.7m）と白い箱（一辺0.5m）はエフェクトではない。位置は撮影台により異なる。箱が流路を遮っている場合は撮影台の位置を直し、素材欠落と取り違えない。
- 煙玉の残りがどれか分からない時は、`plan` の行ごとに「遅れ＋寿命」を計算して、その時刻にまだ生きている行を探す。

- 何が写っているか分からない物は、コードのどの部品かを突き止めてから判断する。推測で「不具合」と書かない。
- 小さくて判断できない時は `--dist` で寄って撮り直す。判断できないまま「良さそう」と書かない。
- カメラは斜め上の横から見ている。水平に回る物（陣の周りを回る泡など）は、高さがそろうと横一本の線や列に見える。不具合ではない。気になるなら高さをばらつかせる。

## 5. 報告の書き方

### 報告を書く前の関門（ここで必ず立ち止まる）

次の2つを数える。
- 直して撮り直した回数（最初に作って撮ったのは0回目。数えない）
- いま不合格の問いの数

**不合格が1つ以上あり、直した回数が3回未満なら、報告を書かない。次の直しに進む。**
直した回数が3回に達したら、不合格が残っていても報告してよい（残りを先頭に書く）。上限は6回。同じ不合格が2回直しても変わらない時は、数値の調整をやめて、部品の選び方（1章の表）から考え直す。
「次にやること」「直すなら〜が必要」と書きたくなったら、それは報告ではなく次の周の作業。書かずに実行する。
これまでの試行では、4人中4人がここで止まった（不合格と直し方を自分で書いたのに、直さず報告した）。

1周は「観察した問題→原因の仮説→形・動きの変更→同じ時刻/構図で比較」。一番目立つ問題1〜2個に絞る。画像を再出力しただけ、字幕や資料を足しただけでは改善の1周に数えない。小修正や分類だけの変更へ無関係な再撮影・全テストを3回強制しない。問題が残る新作/作り直しは上記の改善ループを続ける。


- 見た画像の種類（全体 / 動き / 終わり）を書く。見ていない物を「確認した」と書かない。
- 「多層」「流れる」「固体感がない」は、問い3〜5に画像で答えられた時だけ使う。作り方（wisp を使った等）は根拠にならない。
- 動画は見られない。連続コマで確かめた、と正確に書く。
- 周ごとに「何周目：何を変えた／どの問いが不合格だった」を1行ずつ書く。
- 依頼主が画像だけを送ってきたら、作業を続ける合図ではない。その画像について問い1〜8に答える。

## 7. パックの大・中・小は演出と装飾の量（2026-10-09のユーザー訂正）

- 小：主役1系統を中心に、補助は最大1系統程度。簡潔で用途がすぐ読める。
- 中：主役に2〜3系統の補助・装飾が因果と時差を持って加わる。
- 大：複数の主展開と4系統以上の補助・装飾を組み合わせ、豊かな展開が読める。
- この目安は同じ物理スケールで比較する。拡大、カメラ接近、粒数の単純増加、同じ形の色違いだけで昇格させない。
- カタログに `complexity_class` と `composition`（主役/補助/装飾）、分類理由を残す。`effect_size`は独立した物理スケール。旧`size_class`は互換用で分類へ使わない。
- 同じ主役を描くための3枚の材質は、3系統の演出として水増ししない。床にも、衝突痕・流入・反響・紋章など本文との関係を持たせる。全素材へ同じ輪を置かない。
